1行业标杆调研

调研目标不是找「好看的仪表盘」，而是找能在权威数据场景长期存活的做法：谁在解决与我们相同的三个矛盾——精度 vs 噪声、密度 vs 可读、透明 vs 简洁。

调研得出的三条结论

  1. 权威感来自可核查的元数据，不来自视觉装饰。所以我们的「高端」路线不是加渐变和发光，而是把来源、带宽、样本量、滞后、修订痕迹做到每个数字都能被追问，并把这些字段变成契约。当前 CSS 里的 --glow-accent 与 body::before 的四层渐变网格，属于要移除的一类。
  2. 精度场景下，密度要分层而不是一刀切。首屏只给「一个结论 + 一个主图」，密度通过粒度切换（日/周/月）与按需展开获得，而不是同屏堆 18 项。
  3. 规范若不能自动判定，就等于没有规范。本次宪法条款几乎全部靠人肉遵守；改一次代码就回归一次（历史上 lang=zh_CN 静默截断、HS 漏码 71082000 两次事故，都是「有约定、无门禁」的直接后果）。因此门禁优先级 高于 视觉重构。

2后端架构规范

2.1 分层与依赖方向（单向，禁止反向）

官方源 HTTP
   ↓ fetchers.js        纯取数 + 纯解析（重试/超时/反爬退避；不含业务判断）
   ↓ cache.js           唯一缓存层（key = JSON.stringify([src,start,end])）
   ↓ indicators.js / sheets.js / summaries.js   计算 + 交叉验证 + 纠错
   ↓ integrity.js       通用不变量（被上面三者共同引用，不反向依赖它们）
   ↓ store.js           原子落盘（data/<id>.json）
   ↓ server.js          路由 + 聚合 API（不含数据加工逻辑）
   ↓ core/api.js → core/store.js → ui/* · chart.js   （前端侧唯一通路）
B-1 插件化

新增指标只允许新增 indicators/*.json；若需要新数据源，只允许在 fetchers.js 增加一个 provider 分支并复用既有 request()。禁止在 server.js 或前端出现任何取数逻辑、禁止硬编码序列 ID 列表（自动发现：按 order 排序读取目录）。

B-2 校验腿四型，必须择一且声明机制

每个指标必须声明 checkKind（人类可读机制名）与其 legs[].check，且只能落入四类之一：
① 官方双源逐点（不同机构，同量纲，mode:"abs"）— 如 NY Fed ↔ FRED、HMRC ↔ UN Comtrade；
② 同机构不同口径逐点（同一交易/标的的两种独立聚合）— 如 FDR007 ↔ FR007、Shibor 报价 ↔ 回购成交；
③ 恒等式（派生值必须等于已入库分量之差，provider:"series" + minus）；
④ 关系带宽（比值/差值带，mode:"ratio"/"diff" + band，可 align:"month-mean" 双向对齐）。
禁止把 ②③④ 在 UI 或文档中表述为「第二机构交叉验证」。

B-3 阈值溯源（硬约束）

任何 band、range、maxAbsJump、maxRelJump、maxLagDays 都必须带 source 字段：{sample, window, statistic}，例如「2364 个重叠日 · 2016-11→2026-11 · min/max」。无溯源的阈值一律判失败。这条直接针对历史事故：拍脑袋的带宽要么误报、要么形同虚设。

B-4 三条红线（不可豁免）

不造数：缺口只允许留空并说明（源端未发布 / 授权快照缺失）。
不静默替换：改值必须写 corrected:{from,to,by}，且仅在「主源通不过不变量而校验源通得过」时发生。
不绕过防护：遇到 WAF/反爬（LBMA、港交所类端点）一律放弃并透明标注，禁止伪造 UA 轮换、验证码绕过或代理绕路。

B-5 降级语义

校验腿失败（限流、参照未入库、无重叠日期）绝不阻塞主源入库，但必须记入 validation.checkErrors 并在 UI 报「本期未获并行确认」；自检 fail 触发一次绕缓存重取；冷启动依赖未就绪触发一次补跑。源端能力限制（如 LPR 接口恒回 12 期、Excel 数值列为空）写进 description 与 integrity.source，不外推。

B-6 契约稳定

/api/indicators/:id 响应必须含 schemaVersion、id、updatedAt、validation{checked,matched,mismatched,corrected,kind}、integrity{verdict,counts,notes,flagged}、points[]（字段集合固定：date,v|ohlc,ok,suspect,corrected）。字段只增不减；删除字段视为破坏性变更，必须先补前端消费者再删。

3前端架构规范

3.1 结构与 SSOT

  • core/api.js = 唯一网络出口；core/store.js = 唯一状态与键控差分；core/derive.js = 纯函数派生（无 DOM、无副作用）；chart.js = 唯一 ECharts 触点；app.js = 唯一组合根。
  • 一切可复用 UI 必须在 ui/ 组件族内并提供导出；页面代码不得直接写 innerHTML、不得内联 style.*、不得新增只有单个页面使用的一次性样式类（先去组件族找同类，没有再入族）。
  • 数字/单位/日期的格式化只允许经 derive.js 的 fmtVal / fmtPoint / seriesLabel；出现第二处格式化实现即为缺陷。

3.2 视觉规范：极简 · 克制 · 高端

原则：颜色只承担语义，层级由表面色阶 + 留白 + 字重承担；装饰性渐变、发光、彩色描边一律删除。

F-1 一屏一主角

指标页：主图 + 一行结论 + 徽标条；汇总页：表格 + 校验徽标；资产表页：结构条 + 明细。任何新增元素必须先回答「它挤掉了什么」。

F-2 不只是用颜色传达

存疑点 = 红色描边 且 空心菱形 且 tooltip 文字；改值点 = 金色描边 且 tooltip 显示「改前→改后·依据」。满足 WCAG 1.4.1 / 1.4.11。

F-3 可达性

全部交互可键盘到达，焦点环可见（2px，offset 3px）；正文对比度 ≥ 4.5:1、大字与控件/图形 ≥ 3:1；文本 200% 缩放不丢内容；320px 宽度单列重排无横向滚动。

4门禁（Gate）

落地形态：零依赖 tools/gate.mjs，一条命令跑全部；任一失败以非零码退出且不得加豁免。package.json 增加 "gate": "node tools/gate.mjs" 与 "gate:strict"。

5执行计划

串行推进，每阶段一个可回滚提交；P1（门禁）先于 P2（视觉），因为视觉改动数量大，必须先有能兜住回归的网。

P0 · 基线与冻结 0.5 天

  • 建立 tools/gate.mjs 骨架与 --report；把本轮实测覆盖率快照写入 docs/baseline.json（19/19 校验腿、Σchecked 23 988、ΣuncheckedDates 136、已知缺口清单）。
  • 清理仓库噪声：把 server.log 移出跟踪并加入 .gitignore；已执行：negctl.mjs 与 run-update.mjs 均迁至 tools/（G4 门禁路径同步）；run-update 不再自带一份更新循环，只调用 backend/lib/pipeline.js（默认按水位线增量，--force 才全量重建）。

完成定义：npm run gate 能跑并如实报红（此时只要求 G0/G4 绿）。

P1 · 门禁补全（最高优先） 1.5 天

  • G1/G2/G3：为 19 个指标补齐 integrity.source（多数带宽已有实测值，只差把样本量与区间写成字段）；把「无溯源即失败」的断言打开。
  • G5：唯一性检查（api/chart/derive/ui 索引），并把现有硬编码计数打进报告。
  • G4：负向对照并入 gate（含注入命中数断言）。

完成定义：G0–G5 全绿；--report 输出与 docs/baseline.json 一致；故意破坏一处（改错一个 band 的 source）能被拦住，随即还原。

P2 · 令牌与视觉收敛 2 天 · 6 次可回滚提交

  • P2.1 令牌重写：三级表面 + hairline + 4pt 栅格 + 6 档字号 + 3 档时长；删 --glow-accent、body::before/after 渐变与网格。
  • P2.2 字体：取消展示字体，数值改 tabular-nums；只依赖系统字体（避免第三方字体许可风险）。
  • P2.3 组件族对齐：Badge / RateTile / SeriesToggles / Toolbar / Sidebar 按新令牌重排（结构不变，仅层级与密度）。
  • P2.4 图表去装饰：去网格、中性轴名、单色浅面积、5 色上限。
  • P2.5 密度分层：首屏「一行结论」重写为短句；术语解释归入 tooltip。
  • P2.6 存疑/改值标记补第二提示（形状 + 文字）以满足 1.4.1。

完成定义：G6 绿（对比度、缩放、溢出）；浏览器 1280×800 与 375×812 实测截图与 DOM 断言通过；硬编码计数 = 0。

P3 · 契约版本化 1 天

  • API 加 schemaVersion，前端按版本兼容读取；字段只增不减成为 G1 的附加断言。
  • 汇总行的校验标签由后端 checkKind 生成，删除前端里任何写死的「官方双源」措辞。
  • 更新日志规范化为单行结构化字段（id/points/checked/matched/corrected/suspect/verdict），便于脚本消费。

完成定义：全站搜索不到与后端重复的数据结论文案；/api/status 一次调用即可产出全部门禁所需指标。

P4 · 度量与遗留 持续

  • 度量看板（见 §6）进 --report，每次改动留档。
  • 遗留项按「诚实标注」维护，不造数填补：PBOC 货币当局资产负债表（任务 #17）、LPR 源端 12 期限制、CDS 授权快照缺失、港交所 AI 指数与 ICE BofA OAS 单源。

完成定义：每个未闭合项都能被追问「为什么不可得、试过哪些端点、返回什么」，答案来自实测记录而非推测。

本计划明确不做

  • 不引入任何 npm 依赖（构建、框架、lint、图表库均不引入）——宪法要求零依赖运行，且现状已证明够用。
  • 不做自由拖拽布局、主题市场、登录/多用户、SSR。
  • 不为「视觉达标」而降低数据密度到不可读：精度场景的小数位与滞后声明优先于美观。
  • 不接入需要绕过 WAF 的端点；宁可留透明缺口。
