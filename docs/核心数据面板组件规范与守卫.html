2调研：经典金融数据页怎么把"多参数"叠到一张图上

结论先行：业界成熟做法高度一致——一个图表容器 + 一份数据集契约 + 一组"层(layer)"声明 + 一张类型注册表；轴、区间、图例是这份声明的属性，而不是各自实现的分支。本项目当前是三个容器 + 三份内联算数 + 三套交互。

3组件规范：ChartPanel（SSOT）

以下 10 条为图形层宪法。每条给出可判定命题与今天状态，判定手段在第 5 节写成门禁。

C-1 · 单实例单出口（hard）

全站只允许一个模块持有 ECharts 出口；实例由注册表按容器 id 管理，禁止模块级 let xxxInst。API 面固定为 6 个方法，渲染入口只有 update。

// frontend/js/core/chart-panel.js —— 全站唯一 ECharts 出口
mount(id, el)          // 注册容器；同 id 重复 mount 复用实例（幂等）
update(id, spec, ds)   // 唯一渲染入口：声明(spec) × 数据(dataset) → option
setWindow(id, win)     // 唯一区间入口（preset / 拖拽 / 联动 共用）
setSelected(id, sel)   // 唯一图层开关入口（图例 ⇄ store 的正门）
dispose(id)            // 释放实例并从注册表摘除
instances()            // 自省：供 G18 断言「实例数 == 容器数」

今天：红　3 个实例、3 个渲染入口、6 个 setOption 调用点、5 处模块级可变状态。

C-2 · 声明式 spec，渲染层零业务分支

每个图形页一张 charts/<id>.json，渲染层只解释 spec。新增一页 = 新增一个 JSON 文件，不改 app.js、不改 chart-panel.js（热插拔验收实验）。

单位换算、环比、月度对齐、日期并集、OHLC 聚合、缺值填充一律在 core/dataset.js（纯函数）或后端 aggregate.js 完成。渲染层拿到的必须是「已对齐、已定标、可直接编码」的列。

C-5 · 轴解析唯一化

resolveAxes(layers, spec.axes) 是唯一决定「几根轴、哪一侧、偏移多少、网格留白多少、哪根轴画 splitLine」的函数；shared（同尺度真比较）与 independent（异尺度看相关）必须显式声明。布局常量（当前 offset: idx * 52、grid.left = 58 + 52 * n）进 token。

今天：红　3 种 Y 轴写法（:127 / :232 / :306）、3 处 grid 定义（:112 / :217 静态，仅 :411 按轴数派生）、1 个魔法数 52、1 处硬编码轴名"万亿美元"（:235）。

C-6 · 多参数叠加是一等能力，且有上限与降级

任意指标可与任意指标叠加，同轴或异轴由 spec 声明；叠加集合属于 store 状态（与粒度、区间并列持久），不属于某个渲染器的参数。规则：同轴 ≤3 条（真比较）、异轴合计 ≤5 条；超限组件拒绝渲染并给出拆分建议（依 SSRS/业界 3–5 条线准则）。合成序列（差值、比值）由后端产出，带 checkKind，绝不在前端临时算。

今天：红　仅 renderGold 支持多序列；:152 与 :244 结构上写死单序列。叠加页取数靠 store.js:125 前端并发 N 次 getSeries 手工拼装。

C-7 · store 是唯一状态源（单向数据流）

图例点击 / 区间拖拽等 ECharts 事件 → store action → update 重渲染。渲染层不得记住任何业务状态：无模块级变量、无 goldCats 式缓存、无 onGoldLegend 式专用回调。跨图联动（同一时间窗广播到多图）由面板注册表承担。

今天：红　5 处模块级可变状态；onGoldLegend（:437）为单页定制回调。

C-8 · 交互与文案单一引擎

一份 buildWindow()、一份 slider 样式、一份 buildTooltip(spec) 工厂。tooltip 文案由 spec 的 columns[] 从 SSOT 派生——校验结论、改值留痕、存疑说明、发布滞后四段口径全站唯一，措辞不得在两个 formatter 里各写一遍。

今天：红　3 个 formatter 闭包、3 段区间应用代码、2 份 slider 样式。

C-9 · 视觉只出自 token

图形层零 hex：序列色取 --hue-1…n 或指标配置里的 token 名（而非 hex）；标记色取 --danger（存疑）与 --warn（已改值）；文本/轴线/网格取 --ink/--line/--muted。对比度守 WCAG 2.2 AA（正文 4.5:1、图形元素 3:1）。

今天：红　JS 图形层 50 处 hex、配置文件 51 处 hex，而 tokens.css 仅 28 个 token 且无 --hue-* 序列；已知遗留 --faint 对比度 3.92:1 未达正文 AA。

8风险、边界与自我限制

8.1 「不要重复造轮子」不等于「所有图形挤进一个 canvas」

利率条有 10 个 tile（surface:"strip"，app.js:25），每个 tile 一条最多 30 点的微型折线（数据来自 server.js:109 slice(-30)）；若每个 tile 都开一个 ECharts 实例，内存与首屏成本明显上升（本站首屏要求快且零依赖）。判定标准不是"用了几种技术"，而是同一把尺子是否只有一把：折线缩放几何、单位格式、配色来源必须与主图共用同一函数与同一 token；渲染后端可以是 canvas 也可以是 SVG。因此 spark 与 shareBar 保留轻量 SVG 路径，但其几何与配色由 dataset.js 与 token 供给——从"重复轮子"降级为"同一契约的第二种投影"。Ecg.js 是纯装饰波形（不承载数据），豁免但须在文件头注明"非数据图形"，否则被 G19 捕获时无法自证清白。

8.2 统一不得损害图形语义

周/月视图的 OHLC 必须由 candlestick 配方表达；若为了"都用 line"把它拆成开高低收四条线，会丢掉实体/影线的语义，属于错误收敛。signedBar 的正负分色与零线是流量类指标的核心可读性，不能被通用样式表抹平。

8.3 快照式视觉回归是必要非充分

G24 锁的是 buildOption() 产出的结构与几何派生值（可无头运行、可 diff），不锁像素。像素级验证需浏览器截图，而本项目历史实测中截图通道不可用（当时的替代是画布像素读取与 iframe 注入测视口）。因此 S3/S5 仍须真机看页，并在报告里如实写"快照通过 ≠ 视觉无差异"。

8.4 门禁的失效模式

  • G19 结构哈希误报：语义不同而骨架相似的代码会被判重。处置：阈值从最严格起步（完全同构才红），出现误报时细化判定而不是关闭门禁或加豁免清单。
  • 白名单腐蚀：任何"仅这一次"的文件白名单都会变成常驻后门。处置：白名单条目必须带工单号与到期条件，且长度只能减少。
  • 基线放宽换绿：G21 的棘轮基线一旦允许调大即失效。处置：CI 断言"基线值 ≤ 上一次提交值"。
  • runner 缺位：25 条门禁今天全部是纸面命题。这是全站最大欠口，优先级高于本篇任何重构。
