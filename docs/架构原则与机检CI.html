3管道优先：五态与契约

plan      输入：契约 + 水位线 + 能力矩阵     输出：请求计划（区间、模式、分窗参数、预算上限）
fetch     输入：请求计划                    输出：原始响应 + 调用计数/字节数（审计）
validate  输入：原始响应 → 归一化 Map        输出：逐点 ok / mismatch / alt + checkErrors
correct   输入：validate 结果 + 不变量       输出：值（可能改值）+ correction 三件套 + suspect
commit    输入：correct 结果                输出：单事务写 point/revision/run_stat + 水位线推进
publish   输入：DB                          输出：API 视图 + 导出快照（只读，不再取数）
P-1 无旁路

只有 commit 能写主值表；publish 只读。/api/* 与任何脚本直接写库或写文件 ⇒ G16 红。手动回填也必须走五态，只是 mode:"backfill"。

P-2 每态可观测且预算化

每态记录耗时、计数、字节与状态；plan 阶段即产出「预算」——若某指标本轮预估请求数超上限，直接拒绝发起并把该指标标 degraded，避免退化成全量重拉（承接表 1 的 49 请求 / 5.2 MB 实测基线）。

P-3 扩展点即管道接口

新增校验机制（例如未来的恒等式族）= 在 algebra 注册一种 mode；新增源 = 注册一个 Provider；两者都不得改动状态机本身。

4热插拔与零改：判定实验（规范验收法）

验收不是读代码，而是做两个实验。两者都必须在无人工干预下通过：

  1. 资产实验：新增一个指标声明文件（含契约与保障段，取自录制 fixture 的假响应），不碰任何 backend/server.js、frontend/** 文件。要求：该指标出现在 API 列表、页面自动多出标签与轴、校验腿与阈值生效、门禁绿。
    当前不通过：新增面板类型需改 4 个前端文件（表 1 实测）。
  2. 拔除实验：删掉该声明文件。要求：序列从 API/页面消失，历史数据保留但标记 orphan，门禁不因此变红，前端不报错。
    待建：需要 orphan 语义与清理策略（不静默删历史）。

这两个实验由 G12 自动执行（用临时 fixture 在沙箱目录里跑一遍），不是人工检查清单。

触发机制（不靠自觉）

package.json
  "scripts": { "gate": "node tools/gate.mjs", "gate:diff": "node tools/gate.mjs --diff", "gate:selftest": "node tools/gate.mjs --selftest" }

三层触发：
  1) 本地 pre-commit 钩子：git config core.hooksPath tools/hooks（钩子脚本本身入库）→ 跑 G0/G11/G13/G14/G15（秒级）
  2) 提交前完整门禁：npm run gate → G0–G17 全量（含负向对照与沙箱实验，分钟级）
  3) 每日运行后：更新链结束自动跑 G1/G2/G8/G16（数据类），结果写 fetch_run 并进基线快照
CI-1 门禁必须能红（自证有效）

npm run gate:selftest 在临时副本里注入 8 类缺陷（缺校验腿、阈值无来源、旁路写库、内核 import 外层、前端硬编码色、新增面板改了 app.js、provider 不在能力矩阵、重复文案），要求每条对应门禁各自报红，全绿即判「门禁失效」。这一步是整个机制化主张的地基——绿不算证据，红才算。

CI-2 关闭方式唯一

失败只能通过修实现或修规范（并同 PR 更新 specs 与本文件）关闭。禁止调高阈值、加例外清单、注释断言；gate:disable 之类关键字一旦出现即被 G0 判红。

7风险与自限

风险处置
注册表泛滥（把 3 个分支拆成 12 个文件）沿用既有 M-3 新模块准入四条：消费者只有一个的，保持函数形式，不建注册表。G11 只要求「无中心 if 链」，不要求「一切皆插件」。
间接层导致排错变难每个注册项必须可追溯：--report 输出「本次用到的 provider/renderer/surface 键 + 对应文件」，运行记录里保留键名。
拆壳期间行为漂移P2.5 要求字节级回归：同一天数据在拆壳前后跑出的 data/export/*.json 必须完全一致，diff≠0 不得合并。
门禁过严导致拒绝正当变更正当变更走「先改规范」通道（S-2），并在同 PR 更新 specs/gates.md 与本文件；规范变更本身就是被审计的产物，而非绕过。
把机检当质量本身机检只证明结构合规。数据正确性仍靠 G4 负向对照与端到端实测；「CI 绿」不作为任何一条结论的证据（本项目纪律）。

验收口径：九条原则中任何一条若没有对应门禁与非零退出码，就不算写入规范；任何门禁若无法被 --selftest 证明能红，就不算存在。最终判据只有一句——新增一个数据资产，git diff --name-only 里不得出现 server.js 与 frontend/。
